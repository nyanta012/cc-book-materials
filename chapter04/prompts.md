# 第4章 プロンプト集

本文に掲載しているプロンプトと同じものです。コピーして、Claude Codeパネルの入力欄に貼り付けて使ってください。

第4章では、VS Codeの **File → Open Folder...** で `chapter04/terms-review/` フォルダを開いた状態で使う前提です。

## 4-3　英文規約を日本語で読む

```text
@nyanta_corp_terms_excerpt.txt のみを読み、
1ファイル完結のオフラインでも読めるHTMLビューアを作ってください。
読者は、契約や法務の知識がない日本語話者です。
英文の原文と日本語訳を並べて表示してください。
専門用語や背景知識が必要な箇所にはコールアウト枠でわかりやすく表現してください。
視覚的に読みやすい配色とレイアウトにし、本文・見出し・コールアウトが見分けやすく、長文でも疲れない配色にしてください。
結果は terms_viewer.html として保存してください。
```

## 4-4　チェックリストで仕分ける

```text
@nyanta_corp_terms_excerpt.txt と @our_review_checklist.md のファイルのみを読み、
チェックリストの各項目に規約の該当条項を引用して
OK / 要確認 / NG を判定する、
1ファイル完結のオフラインでも読める HTML レビュー結果を作ってください。
読者は、契約や法務の知識がない日本語話者です。

各判定行には次の3つを必ず含めてください。
- 判定バッジ（OK / 要確認 / NG）
- 根拠条項へのアンカーリンク（クリックで条項本文にジャンプできる）
- なぜその判定になったのかの短い解説
  （条項のどの文言がチェックリストのどの基準を満たす／満たさないのかを1〜3文で説明する）

判定の根拠には、条項番号と英語原文の逐語引用を付けてください。
例外や但書で条項の意味が変わる場合は、その部分も省略せず引用してください。
判定理由には、読ませた2ファイルに書かれていない業界標準や一般論を補わないでください。

規約本文は英語の原文と日本語訳を二列で並べて表示してください。
引用できる条項が出せない項目は自動的に「要確認」とし、解説欄にもその旨を書いてください。

視覚的に判定結果と根拠が一目で把握できる配色とレイアウトにしてください。
OK / 要確認 / NG がバッジで見分けやすく、判定行から根拠条項への動線が明確になるようにしてください。

結果は review_result.html として保存してください。
```

## 4-5　Rewindで数手前に戻す

4-4の続きのセッションで使います。1つ目は`/rewind`で取り消す練習用の追加指示、2つ目はフォークで開いた新しいタブの入力欄に、分岐点の指示文の代わりに入れて送る質問です。

```text
review_result.html の規約本文から英語の原文の列を消して、日本語訳だけの1列にしてください。
```

```text
再委託先（Subprocessor）を追加するとき、当社への通知はどう定められていますか。該当する条項を挙げて説明してください。
```
